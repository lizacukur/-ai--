# Публикация объявления: Автозагрузка

**Этот этап работает только в Claude Code.** В Claude Cowork его нет: песочница
Cowork ходит в сеть по закрытому списку доменов, `api.avito.ru` туда не входит.

## Два условия, которые проверяются до всего остального

### 1. Прямого метода создания объявления в API нет

Проверено по официальному спеку: из 238 методов создать объявление напрямую
можно только для вакансий (`POST /job/v2/vacancies`). Для всех остальных
категорий публикация идёт **только через Автозагрузку** — XML-фид лежит по
публичной ссылке, Avito забирает его сам.

### 2. Автозагрузка требует платного тарифа

**Проверь одним запросом, прежде чем что-то собирать:**

```
GET /autoload/v2/profile
```

- **200** — чтение настроек доступно, можно идти дальше.
- **403 на `POST /autoload/v2/profile`** с текстом
  «Создание/обновление профиля недоступно» — тариф не позволяет заводить фид.

Важная тонкость, проверенная на живом кабинете: **чтение профиля может
возвращать 200 и даже `autoload_enabled: true`, а запись при этом быть
заблокирована.** То есть «в ответе написано, что автозагрузка включена» ещё
не значит, что фид получится создать. Проверять надо именно запись.

В интерфейсе это выглядит как страница `avito.ru/autoload/settings` с
надписью «Автозагрузка недоступна» и кнопкой выбора подписки.

Если запись закрыта — скажи об этом сразу и не заставляй человека собирать
фид впустую. Варианты: подключить подписку с Автозагрузкой либо публиковать
объявление руками через личный кабинет (текст и картинки уже готовы, это
несколько минут).

## Поля объявления берутся у самой Avito

Не угадывай набор тегов. Спроси справочник:

```
GET /autoload/v1/user-docs/tree                      # дерево категорий
GET /autoload/v1/user-docs/node/{node_slug}/fields   # поля конечной категории
```

`node_slug` должен быть **листом** дерева — на промежуточной категории API
вернёт 400 с прямым указанием на это.

### Две ловушки в справочнике полей

**Зависимые поля.** У поля в `content[].dependencies` бывает условие вида
«применимо, только если в другом поле указано такое-то значение». Поле,
помеченное `required: true`, может вообще не относиться к твоему случаю.
Пример из категории обучения: `SubjectOrSpecialty` обязательно только при
`Speciality = "Рабочие специальности и безопасность"`, а при
`Speciality = "IT, бизнес"` применяется совсем другое поле — `Specialty`.
Всегда читай `dependencies_text` перед тем, как включить поле в фид.

**Формат фида.** У поля есть `feed_format`: `xml`, `excel` или оба. В XML-фиде
фотографии передаются тегом `<Images>` с вложенными `<Image url="..."/>`.
Поля `ImageUrls` и `ImageNames` помечены обязательными, но относятся
**только к формату Excel** — в XML их быть не должно.

## Структура файла

Корень `<Ads formatVersion="3" target="Avito.ru">`, внутри `<Ad>` на каждое
объявление, кодировка UTF-8. Длинные тексты — в `CDATA`, чтобы не экранировать
вручную.

Два тега решают судьбу объявления:

- **`<Id>`** — твой собственный уникальный идентификатор. По нему Avito
  узнаёт объявление от выгрузки к выгрузке. **Менять его нельзя**: смена `Id`
  читается как новое объявление и ведёт к дублям и блокировкам.
- **`<AvitoId>`** — номер уже существующего объявления на Avito. Для нового
  объявления **не заполняется**. Заполняется только чтобы «усыновить» в фид
  объявление, размещённое ранее вручную. Осторожно: `AvitoId`, скопированный
  в другую строку, перезапишет исходное объявление.

## Фотографии

- прямые публичные HTTPS-ссылки либо публичные ссылки Яндекс Диска;
- **только JPEG и PNG** — WebP не принимается, конвертируй заранее;
- до 25 МБ на файл, **не более 10 фотографий** на объявление;
- ссылка должна открываться без авторизации и отдавать именно изображение;
- чтобы заменить фото, нужна **другая ссылка**: новое изображение по старому
  адресу Avito не перечитает.

## Хостинг фида и фотографий

Нужен бесплатный статический хостинг с HTTPS. Рабочий вариант — публичный
репозиторий на GitHub.

**Предпочитай GitHub Pages (`*.github.io`), а не `raw.githubusercontent.com`.**
Причина: raw отдаёт `.xml` с заголовком `content-type: text/plain`, и примет
ли Avito такой фид — непроверено. GitHub Pages отдаёт `.xml` с корректным
XML-типом. Для картинок raw работает нормально: `content-type: image/jpeg`
проставляется правильно.

Перед регистрацией фида проверь каждую ссылку:

```
curl -s -o /dev/null -w "%{http_code} %{content_type}\n" <url>
```

## Продвижение прямо из файла

Через фид подключается и продвижение, отдельными вызовами это делать не нужно:

- **`<AdStatus>`** — разовые услуги: выделение цветом, XL-объявление,
  увеличение просмотров. За загрузку подключается только одна услуга.
- **`<Promo>`** — настройка цены целевого действия (CPA): ручной режим со
  своей ставкой и дневным лимитом либо автоматический с бюджетом на период.

Любой из этих тегов тратит деньги с кошелька Avito. Ставить их без явного
разрешения человека нельзя.

## Порядок выгрузки

```
POST /autoload/v2/profile            # зарегистрировать ссылку на фид и расписание
POST /autoload/v1/upload             # запустить выгрузку немедленно
GET  /autoload/v4/uploads/current    # что происходит прямо сейчас
GET  /autoload/v4/uploads/last_successful         # итог последней выгрузки
GET  /autoload/v4/uploads/last_successful/items   # результат по каждому объявлению
```

Тело `POST /autoload/v2/profile` требует `feeds_data` (имя и ссылка на фид),
`schedule`, `autoload_enabled` и `report_email`. Пустое расписание (`[]`) —
валидное состояние: фид зарегистрирован, но сам по себе не запускается.

`POST /autoload/v1/upload` не принимает параметров: он запускает выгрузку из
ссылки, уже сохранённой в профиле. **В течение часа так можно запустить
только одну выгрузку.**

Результат разбирай по объявлениям и называй ошибки словами человека, а не
кодами. Опубликовалось не всё — скажи, что именно не прошло и почему.

## Сначала выясни, не управляется ли профиль фидом уже сейчас

**Это проверяется до любых действий с автозагрузкой.** Объявление могло быть
создано фидом раньше — например, подрядчиком или прошлой подпиской, которая
закончилась. Тогда «завести фид с нуля» означает подменить живой файл, и все
строки, которых в новом файле нет, рискуют уйти с публикации.

Признак виден в карточке объявления:

```
GET /core/v1/accounts/{user_id}/items/{item_id}/
```

Поле **`autoload_item_id`** — это `Id` строки из фида. Если оно заполнено,
объявление создано автозагрузкой, а не руками. Значение говорит и о логике
прошлого фида: идентификаторы вида `region_04`, `region_17` означают, что
фид раскатывал одно предложение по регионам.

Проверяй **выборочно по разным группам объявлений**, а не одно: профиль
часто смешанный — региональная сетка из фида плюс несколько карточек,
добавленных руками.

Что делать, если фид уже был:

1. **Не регистрируй новый файл вместо старого.** Новое объявление
   добавляется **строкой в существующий фид**, с сохранением всех прежних
   `Id`.
2. Выясни у человека, где лежит старый файл и кто его вёл. Часто это
   подрядчик или сервис-посредник, и доступ придётся восстанавливать.
3. Если старый файл потерян — новый фид должен содержать **все** текущие
   объявления с их `AvitoId`, иначе они осиротеют. Это разовая, но
   обязательная работа.

Отдельно: если в одном городе фид поставил два объявления с одинаковым
заголовком, площадка снимает их как дубли. При разборе блокировок сверяй
заголовок вместе с городом и идентификатором строки фида — обычно видно,
что виноват не текст, а логика размножения по регионам.

## Риск, о котором нужно предупреждать заранее

По вторичным источникам, объявления, **которых нет в файле, снимаются с
публикации** на следующем цикле. Настройки «не снимать» найти не удалось, и
существует ли она — не подтверждено.

На аккаунте, где уже есть объявления, созданные вручную, действует жёсткое
правило: **до первой выгрузки предупреди человека и сделай страховку.**

1. Выгрузить все текущие объявления (`GET /core/v1/items` со всеми статусами)
   и сохранить их `id`, заголовки и цены — чтобы всё было восстановимо.
2. Проверить в кабинете, есть ли настройка поведения для объявлений вне файла.
3. Первую выгрузку делать **одним тестовым объявлением**, в ручном режиме,
   не включая расписание.
4. По отчёту убедиться, что остальные объявления не пострадали, и только
   после этого расширять фид.

Никогда не включай расписание регулярных выгрузок на аккаунте с ручными
объявлениями, пока поведение не проверено на практике.

## Что в этой цепочке проверено, а что нет

Честно разделяй, когда рассказываешь человеку:

**Проверено на живом кабинете:** авторизация, чтение профиля автозагрузки,
дерево категорий, справочник полей с зависимостями, хостинг фото с корректным
типом, сборка валидного XML, тарифный замок на записи профиля (403).

**Не проверено (упирается в платный тариф):** приём фида по ссылке с
`text/plain`, прохождение XML через валидатор Avito, `POST /autoload/v1/upload`,
содержимое отчётов, поведение объявлений вне фида.

Не выдавай непроверенное за работающее. Если человек собирается платить за
подписку — он должен знать, что именно ещё не подтверждено.

## Деньги

Размещение объявлений сверх лимита тарифа Avito тарифицирует по своим
правилам — в спецификации есть тег `ListingFee`. Публикация через фид не
делает размещение бесплатным. Если человек рассчитывает на «бесплатно»,
скажи прямо: бесплатна автоматизация и хостинг, но не сами размещения.
