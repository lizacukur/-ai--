# Публикация объявления: Автозагрузка

## Главный факт

**В Avito API нет метода «создать объявление».** Проверено по официальному
спеку: единственное исключение — вакансии (`POST /job/v2/vacancies`), для всех
остальных категорий прямого создания нет.

Публикация идёт **только через Автозагрузку**: XML-файл лежит по публичной
ссылке, Avito сам за ним приходит и создаёт объявления. Через тот же файл
задаются цена, фото и продвижение.

Не изображай, что объявление ушло на площадку, если фид не собран и выгрузка
не подтверждена отчётом.

## Доступность

Проверяется одним запросом:

```
GET /autoload/v2/profile
```

Ответ показывает `autoload_enabled`, текущие фиды (`feeds_data`), расписание
и режим (`uploadMode`). Если эндпоинт отвечает 403 — автозагрузка на аккаунте
недоступна, обычно из-за тарифа: по вторичным источникам нужен «Расширенный»
или «Максимальный» и профиль компании, но официально это не подтверждено —
проверяй ответом API, а не предположением.

## Поля объявления берутся у самой Avito

Не угадывай набор тегов. Спроси справочник:

```
GET /autoload/v1/user-docs/tree                      # дерево категорий
GET /autoload/v1/user-docs/node/{node_slug}/fields   # поля конечной категории
```

`node_slug` должен быть **листом** дерева — на промежуточной категории API
вернёт 400 с прямым указанием на это. Ответ даёт по каждому полю: тег,
обязательность, тип и допустимые значения справочников.

Состав обязательных полей сильно зависит от категории. Для услуг это обычно
около десятка полей, включая специфичные справочники вида «чем вы занимаетесь»
и «как вы работаете», которые в других категориях отсутствуют.

## Структура файла

Корень `<Ads formatVersion="3" target="Avito.ru">`, внутри `<Ad>` на каждое
объявление, кодировка UTF-8.

Два тега решают судьбу объявления:

- **`<Id>`** — твой собственный уникальный идентификатор. По нему Avito
  узнаёт объявление от выгрузки к выгрузке. **Менять его нельзя**: смена `Id`
  читается как новое объявление и ведёт к дублям и блокировкам.
- **`<AvitoId>`** — номер уже существующего объявления на Avito. Для нового
  объявления **не заполняется** (номер присвоится сам). Заполняется только
  чтобы «усыновить» в фид объявление, размещённое ранее вручную. Осторожно:
  `AvitoId`, скопированный в другую строку, перезапишет исходное объявление.

## Фотографии

Передаются ссылками, файлы Avito скачивает сам:

- прямые публичные HTTPS-ссылки либо публичные ссылки Яндекс Диска;
- JPEG или PNG, до 25 МБ на файл;
- **не более 10 фотографий**, остальные игнорируются;
- ссылка должна открываться без авторизации и отдавать именно изображение.

Бесплатный хостинг под фид и фото: публичный репозиторий на GitHub с
включённым GitHub Pages. Отдаёт статические файлы по HTTPS, стоит ноль.
`*.github.io` предпочтительнее `raw.githubusercontent.com`.

## Продвижение прямо из файла

Через фид подключается и продвижение, отдельными вызовами это делать не нужно:

- **`<AdStatus>`** — разовые услуги: выделение цветом, XL-объявление,
  увеличение просмотров. За загрузку подключается только одна услуга.
- **`<Promo>`** — настройка цены целевого действия (CPA): ручной режим со
  своей ставкой и дневным лимитом либо автоматический с бюджетом на период.

Любой из этих тегов тратит деньги с кошелька Avito. Ставить их без явного
разрешения человека нельзя.

## Порядок выгрузки

```
POST /autoload/v2/profile            # зарегистрировать ссылку на фид и расписание
POST /autoload/v1/upload             # запустить выгрузку немедленно
GET  /autoload/v4/uploads/current    # что происходит прямо сейчас
GET  /autoload/v4/uploads/last_successful         # итог последней выгрузки
GET  /autoload/v4/uploads/last_successful/items   # результат по каждому объявлению
```

Если расписание настроено, `upload` не обязателен: Avito придёт за файлом сам
в свой слот. Расписание задаётся днями недели (0 — понедельник) и часовыми
слотами по Москве.

Результат разбирай по объявлениям и называй ошибки словами человека, а не
кодами. Опубликовалось не всё — скажи, что именно не прошло и почему.

## Риск, о котором нужно предупреждать заранее

По вторичным источникам, объявления, **которых нет в файле, снимаются с
публикации** на следующем цикле. Настройки «не снимать» найти не удалось, и
существует ли она — не подтверждено; официальную документацию проверить не
получилось.

Поэтому на аккаунте, где уже есть объявления, созданные вручную, действует
жёсткое правило: **до первой выгрузки предупреди человека об этом риске и
сделай страховку.**

Безопасный порядок:

1. Выгрузить все текущие объявления (`GET /core/v1/items` со всеми статусами)
   и сохранить их `id`, заголовки и цены — чтобы всё было восстановимо.
2. Проверить в кабинете, в разделе Автозагрузки, есть ли настройка поведения
   для объявлений вне файла.
3. Первую выгрузку делать **одним тестовым объявлением**, в ручном режиме,
   не включая расписание.
4. По отчёту убедиться, что остальные объявления не пострадали, и только
   после этого расширять фид.

Никогда не включай расписание регулярных выгрузок на аккаунте с ручными
объявлениями, пока поведение не проверено на практике.

## Деньги

Размещение объявлений сверх лимита тарифа Avito тарифицирует по своим
правилам — в спецификации есть тег `ListingFee`. Публикация через фид не
делает размещение бесплатным. Если человек рассчитывает на «бесплатно»,
скажи прямо: бесплатна автоматизация и хостинг, но не сами размещения.
