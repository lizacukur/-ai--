# API Avito: как спрашивать, чтобы получить правду

Собрано на реальном кабинете методом проб и ошибок — включая ошибки.
Ссылки на конкретные тела запросов: скилл `avito-api`, `scripts/lookup_endpoint.py`.

## Доступ

`POST /token/` (form: `grant_type=client_credentials`, `client_id`, `client_secret`) →
`access_token` на 24 часа. Дальше везде заголовок `Authorization: Bearer <token>`.

Ключи — в кабинете Avito: **Настройки → Avito API → регистрация приложения**.
Раздел появляется только при подключённом платном тарифе.

## Список объявлений — не наступай на грабли со статусом

```
GET /core/v1/items?status=active,removed,old,blocked,rejected&per_page=100
```

**Без параметра `status` API отдаёт только активные объявления.** Если в
кабинете есть старые, снятые или заблокированные — они выпадут молча, и
цифра «объявлений всего» окажется заниженной без единой ошибки в ответе.
Раскладка статусов: `active`, `removed`, `old`, `blocked`, `rejected`.

## Просмотры, контакты, деньги — один запрос, а не три

```
POST /stats/v2/accounts/{user_id}/items
{
  "dateFrom": "...", "dateTo": "...",
  "grouping": "item",
  "metrics": ["views", "contacts", "favorites", "presenceSpending"],
  "limit": 100, "offset": 0
}
```

Постранично через `limit`/`offset`, общее число строк — в `result.dataTotalCount`.
`presenceSpending` — реальный расход по объявлению **в копейках**.

Это основной источник цифр. `stats/v1/accounts/{user_id}/items` (просмотры/
контакты/избранное без денег) существует и работает, но расход не отдаёт —
для полной картины используй только `stats/v2`.

## Продвижение — самая частая ошибка в разборе

У Avito есть **два разных вида платного продвижения**, и их легко перепутать:

1. **VAS-услуги** («Выделение цветом», XL) — разовая покупка на объявление.
   Статус смотрится через `GET /core/v1/accounts/{user_id}/items/{item_id}/`,
   поле `vas`.
2. **CPA-продвижение** («Настройка цены просмотра», оплата за показ/клик/
   сообщение) — отдельный тариф на весь аккаунт («План активен» в кабинете).
   Ставки смотрятся через `POST /cpxpromo/1/getPromotionsByItemIds` с
   `itemIDs`, поле `manualPromotion.bidPenny` (копейки) там, где задана
   вручную. **Деньги списываются даже без ручной ставки** — это тариф на
   весь аккаунт, и видно это только по ненулевому `presenceSpending`.

**Пустой `vas` не значит, что продвижения нет.** Это частая и дорогая по
последствиям ошибка: аккаунт может быть на CPA-тарифе и активно тратить
деньги, а `vas` при этом пустой — потому что он про другую услугу.
Проверка «включено ли продвижение» обязана смотреть на оба признака:
`cpxpromo` (ручные ставки) и `presenceSpending > 0` (сам факт расхода).

Прогноз для BBIP-продвижения (`POST /promotion/v1/items/services/bbip/
forecasts/get`) у многих объявлений недоступен — ответ прямо говорит
«BBIP недоступен для объявления». Это нормальный ответ, не ошибка; в этом
случае прогноз не выдумывается, просто его нет.

## Расход по кабинету — для сверки, не как основной источник

```
POST /stats/v2/accounts/{user_id}/spendings
{"dateFrom": "...", "dateTo": "...", "grouping": "month", "spendingTypes": ["all"]}
```

Даёт сумму без разбивки по объявлениям — полезно свериться с суммой из
`stats/v2/.../items`, но не для поиска дорогих объявлений: для этого нужна
именно построчная выгрузка выше.

## Rate limit

429 встречается при частых запросах подряд (особенно постраничная выгрузка
`stats/v2/items` на профиле с полусотней объявлений). Делать паузу 2–8 секунд
между страницами и повтор с задержкой при 429, а не падать сразу.

## Мессенджер

- `GET /messenger/v2/accounts/{user_id}/chats` — список чатов
- `GET /messenger/v3/accounts/{user_id}/chats/{chat_id}/messages/` — переписка
- `POST /messenger/v1/accounts/{user_id}/chats/{chat_id}/messages` — отправка

Отправлять только после подтверждения человеком, если не разрешено заранее —
это необратимо и видно покупателю.

## Публикация — единственное, чего в API нет напрямую

Метода «создать объявление» не существует. Публикация и массовое редактирование
идут через **Автозагрузку** — файл-фид по ссылке, который Avito забирает сам:

- `POST /autoload/v1/profile` — настройка профиля автозагрузки
- `POST /autoload/v1/upload` — загрузка файла по ссылке
- `GET /autoload/v4/uploads/last_successful` — что реально опубликовалось
- `GET /autoload/v1/user-docs/node/{node_slug}/fields` — поля категории

Пока автозагрузка не настроена — новый текст готовится, а публикуется
руками, это занимает минуты. Не выдавать неопубликованный текст за
опубликованный.

## Что можно менять программно

- `POST /core/v1/items/{item_id}/update_price` — цена
- `PUT /core/v2/items/{itemId}/vas/` — VAS-услуги
- `POST /cpxpromo/1/setManual` / `setAuto` / `remove` — CPA-ставки
- `POST /ratings/v1/answers` — ответ на отзыв

Любое из этих действий тратит деньги или меняет то, что видит покупатель —
спрашивать перед каждым, если не разрешено заранее.

## Рейтинг и отзывы

`GET /ratings/v1/info` (сводка, оценка), `GET /ratings/v1/reviews` (список).
В разделе «Услуги» рейтинг влияет на позицию в выдаче не меньше текста
объявления.
